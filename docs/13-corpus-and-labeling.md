# 13 — Building the Evaluation Corpus Without Reading CVs

The differentiation plan ([doc 12](12-differentiation.md)) puts Turkish hiring
ground truth first, which raises the obvious objection: *someone has to label
hundreds of CVs, one by one.* No. This document is the design that makes the
corpus mostly self-labeling, and it is honest about the part that isn't.

The short version: **most quality signal comes from invariants, not labels.**
Absolute judgments ("this candidate is a 78") are expensive and arguable.
Properties ("the same CV under a different name must score identically") are
free, unarguable, and generated by the hundred from CVs nobody has read.

## 1. Where labels come from, in descending order of trust

| Source | Covers | Cost | Who is trusted |
|---|---|---|---|
| **Invariants** (§3) | fairness, monotonicity, knockout correctness | free | nobody — the assertion follows from the edit |
| **Deterministic rules** | experience floors, location, CEFR, degrees, job-hopping | free | the predicate engine (already the production code) |
| **Oracle ensemble** (§4) | semantic requirements — "real B2B depth?" | model tokens, offline | K independent passes that agreed, with verified quotes |
| **Human** | the disagreements only | ~15 seconds each | the reviewer |

On the shipped b2b-sales case, the split is roughly **57% of labels free from
rules**, the rest ensemble-labeled, and only genuine disagreements reach a
person. A pool of 300 CVs is a queue of a few dozen 15-second decisions, not
300 CVs to read.

## 2. Intake: real CVs in, no personal data stored

`corpus_cli import` runs the production extractor and then
[de-identifies](../src/senthire/evals/deidentify.py) before anything touches
disk:

- names, e-mails, phones and profile URLs are replaced with stable pseudonyms;
- raw text is swept for anything the extractor missed — contact details,
  national ID numbers, birth dates;
- everything screening reasons about (titles, dates, companies, skills,
  languages, education, geography) is preserved exactly.

Pseudonyms are deterministic under a secret salt (`SENTHIRE_CORPUS_SALT`): the
same person always maps to the same fake identity, and without the salt nobody
can map back. The salt never enters the repository; neither do the source PDFs
(`.gitignore`). The de-identified pool is the asset and *is* committed.

KVKK note: de-identification is a safeguard, not a lawful basis. Real
candidate CVs may only enter a corpus where the controller has a basis for
that processing — for our own customers that is a DPA question, and for
sample CVs from a partner it belongs in the agreement.

## 3. Invariants: ground truth nobody labels

From a single unlabeled CV, [`invariants.py`](../src/senthire/evals/invariants.py)
derives twins whose *correct relative outcome is known by construction*:

| Twin | Edit | Assertion | Catches |
|---|---|---|---|
| `fairness` | same CV, differently-coded name | identical score **and** band | name-driven bias, the risk that ends careers and lawsuits |
| `more_experience` | earliest role starts a year earlier | score must not fall | scorer/derived-field regressions, weight-sign errors |
| `weaker_language` | one CEFR level lower | score must not rise | language scoring that ignores its own rubric |
| `knockout` | a hard rule provably violated | gated out, naming *that* rule | silent gate failures, wrong rejection reasons |

Two disciplines keep these honest:

1. **Decline when arguable.** If a spec rewards *less* experience (an
   over-qualification penalty, a job-hopping ceiling), the monotonic twin is
   not emitted. A wrong invariant is worse than no invariant.
2. **Verify the construction.** A knockout twin is re-run before promotion; if
   the edit did not actually trip the rule it names, the twin is dropped and
   reported instead of asserted.

Nine CVs in the reference pool produce 34 twins — 25 pair assertions and 9
gate assertions — with zero human input.

## 4. The oracle ensemble: judging what rules can't

Semantic requirements need judgment, so we buy it offline where cost and
latency don't matter, and we don't trust a single opinion:

- **K passes with different framings** — neutral, advocate ("read as favorably
  as the evidence honestly allows"), skeptic ("assume nothing unwritten").
  Identical prompts run K times mostly reproduce the same bias; deliberately
  opposed framings disagree exactly where a case is genuinely borderline.
- **Evidence verification** — a vote whose quote is not in the document is
  discarded before aggregation, not averaged in. Same discipline the product
  applies in Stage 6.
- **Agreement is the confidence.** The stored label carries the agreement rate,
  so promotion can demand `--min-confidence 0.9` and simply skip the rest.
- **Severity, not just arithmetic.** A met-vs-not_met split goes to a human
  even at 2/3 agreement; a met-vs-partially_met split does not.
- **Unanimous "unknown" is a strong label**, not a weak one: three lenses, one
  of them instructed to read favorably, failed to find the information. That
  is a claim about the document, and it is how *missing ≠ negative* gets test
  coverage.

The oracle is not the production screening model. It is slower, stronger, sees
the full text, and votes with itself — a teacher the cheap production funnel
never sees, which is what makes grading the funnel against it meaningful.

## 5. The human queue

`corpus_cli review` prints one line per genuine disagreement: the requirement,
the competing verdicts, the leading rationale. The reviewer answers "which
reading is right?" — they are not reading a résumé. `--write-template` emits a
JSON file pre-filled with the leading verdict; edit the ones you disagree with,
run `adjudicate`, and the labels are updated with `source: "human"`.

Anything still unresolved simply doesn't get promoted. The suite never guesses.

## 6. Promotion: what becomes a CI gate

`corpus_cli promote` writes a standard golden case ([doc 11 §2](11-mvp-and-scaling.md))
and separates three kinds of assertion, because they are not equally
trustworthy:

- **True by construction** — invariants (§3). These are the backbone.
- **True if the labels are** — per-requirement verdicts and the gate that
  follows. Weakly agreed labels are excluded by `--min-confidence`.
- **Pins, not truth** — band and exact score, written only with `--pin-scores`.
  They catch unintended movement; when a scorer change is intentional you
  re-promote and review the diff.

Ordering assertions (`expected_order_pairs`) are deliberately *not* derived
from the scorer's own output — that would be circular. They come from pairwise
oracle preferences (`rank_pair`), which are unanimous **and** order-independent
(half the passes see the pair reversed to cancel position bias), or they stay
empty.

## 7. The full loop

```bash
export SENTHIRE_CORPUS_SALT=...          # keep out of the repo

python -m senthire.evals.corpus_cli import      --pool satis-2026 ~/cvs/*.pdf
python -m senthire.evals.corpus_cli attach-job  --pool satis-2026 --job b2b --spec spec.json
python -m senthire.evals.corpus_cli label       --pool satis-2026 --job b2b
python -m senthire.evals.corpus_cli review      --pool satis-2026 --job b2b \
                                                --write-template decisions.json
python -m senthire.evals.corpus_cli adjudicate  --pool satis-2026 --job b2b decisions.json
python -m senthire.evals.corpus_cli promote     --pool satis-2026 --job b2b --name satis-b2b
python -m senthire.evals                        # the new case is now a CI gate
```

`--fake-oracle` runs the whole flow offline with a deterministic stand-in, so
the tooling can be tried (and tested in CI) without a single API call.

## 8. Where the next labels come from — for free

The corpus is the cold start. Production is the compounding source, and it
needs no labeling effort at all:

- **Overrides are labels.** When a recruiter overrules a verdict, that is a
  human label on a real job from a real customer — the highest-value kind. The
  override table already records them.
- **Pipeline outcomes are labels.** Which 80+ candidates were actually
  interviewed, offered, hired ([doc 10 §9](10-product-ux.md)) turns screening
  scores into calibration data per org and per vertical.
- Both arrive de-identified through the same import path, and both feed the
  same gate.

That is the moat compounding: every month of real use makes the suite stricter,
and a stricter suite is what a chatbot cannot copy.
